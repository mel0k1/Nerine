**Nerine** — хобби-ОС с упором в скорость, чьё ядро — прежде всего **один большой гипервизор**. Ядро не «запускает программы»: оно изолирует, планирует и наблюдает, а подсистемы — драйверы, сеть, shell — растут поверх как независимые гостевые цветения. Обычному приложению VM не выдаётся: оно живёт в лёгком Sepal-домене. Упавший драйвер здесь не паника ядра, а цветок, который пересаживают.

Названа в честь [Nerine](https://en.wikipedia.org/wiki/Nerine) — южноафриканского цветка с тонкими закрученными лепестками, распускающегося в осенней тьме.

## Сад имён (утверждён)

| Компонент | Имя | Образ |
|---|---|---|
| ОС | **Nerine** | цветок, из которого всё растёт |
| Ядро-гипервизор | **Bulb** | луковица — питает и защищает всё растение |
| Гость-подсистема (VM) | **Bloom** | изолированное цветение на луковице |
| Приложение | **Leaf** | лист — лёгкий процесс без собственной VM |
| Домен защиты | **Sepal** | чашелистик — оболочка, охраняющая Leaf |
| IPC сообщениями | **Nectar** | нектар — то, чем обмениваются цветения |
| Массовая передача | **Pollen** | пыльца — zero-copy перенос данных |
| Shell | **Corolla** | венчик — то, к чему прикасаешься ты |
| Слой безопасности | **Tunic** | сухая оболочка луковицы |
| Жёсткий режим изоляции | **Greenhouse** | оранжерея — изоляция в духе Qubes OS, opt-in |
| Тулчейн | **Многолетник** | perennial — цветок, что возвращается сам, год за годом |

## Родословная

Дизайн сверяется с настоящими гипервизорами и микроядрами:

- **Xen** — доменная модель и путь к минимальному dom0 (dom0less)
- **Jailhouse** — статическое разделение ресурсов между гостями
- **NOVA** — микрогипервизор: компактный TCB как самоцель
- **seL4** — формальная верификация как ориентир доверия
- **managarm** — микроядро Thor и асинхронный Hel: лейны, очереди и kernlets как быстрый путь; VirtualizedSpace / VirtualizedCpu — виртуализация внутри микроядра; bragi-IDL поверх
- **KVM / Firecracker** — Linux-хост и Rust-VMM как промышленные референсы

## Принципы

- **Rust прежде всего** — ядро на `#![no_std]` Rust; C++ только там, где он заслужил место.
- **Код вместо комментариев** — комментарии отвечают на «почему», а не пересказывают «что».
- **Изоляция по умолчанию** — если может быть гостем, значит будет гостем.
- **Быстрый по умолчанию** — Leaf живёт в лёгком Sepal-домене, а не в VM; массовые данные идут через Pollen, минуя копирование.
- **Сад, а не монолит** — подсистемы сажают, заменяют и обрезают независимо.

## Дорожная карта

- [x] **Росток** — freestanding-ядро `no_std`, собирается под x86_64
- [x] **Стебель** — собственный target `x86_64-nerine.json`, вывод в 16550 UART
- [x] **Nectar** — лейны и очереди в духе Hel: SPSC-лейн, очередь в разделяемой памяти с «дверным колокольчиком», спинлоки — всё с юнит-тестами в CI
- [x] **Bulb** — загрузка через Limine, VT-x: настоящий VMX-путь и первый гость; в CI гость идёт через shadow-бэкенд под TCG
- [x] **Pollen** — zero-copy каналы массовой передачи: кольцо зёрен в разделяемой памяти (grant → publish → poll → release, ни одной копии), дверной колокольчик и petal — быстрый путь в ядре по мотивам kernlets
- [x] **Первые цветения** — первый Bloom-драйвер: консоль как изолированный гость; работа приходит по mailbox в разделяемой памяти, «железо» трогается только через IO-exit; в CI идёт через shadow-бэкенд
- [x] **Первые листья** — Leaf в Sepal-домене: ring 3, собственные таблицы страниц, syscall-вход через int 0x80; упавший лист ядро изолирует (sepal:caught), а крона живёт (sepal:alive)
- [x] **Грунт** — реальное железо: LAPIC (EOI, спурьё, x2-режим через MSRs), таймер LAPIC с калибровкой по PIT, первые прерывания через IDT; операнды VMXON/VMCLEAR/VMPTRLD и математика контролов выверены и покрыты тестами в крейте `soil`
- [x] **Corolla** — интерактивный shell: ядру наконец можно говорить. Линейная дисциплина над COM1 (эхо, бэкспейс, Ctrl-U, Ctrl-C), команды на живом состоянии ядра — soil, uptime, nectar, pollen, bloom, vm — и `gh` для оранжереи. Таймер LAPIC продолжает тикать внутри shell'а, поэтому uptime живой; IRQ-путь теперь сохраняет XMM/MXCSR (fxsave) — SSE-код можно безопасно прерывать
- [x] **Greenhouse** — opt-in жёсткая изоляция в духе Qubes: `gh on` ставит стеклянные стены — сад переходит в Hard-режим, где массовая передача идёт через брокера (копия через приватную память ядра), а прямой zero-copy обмен между стенами отказывается; `gh vm` выращивает hard-VM, чья память ограничена собственным EPT (2 МиБ-страницы вокруг фреймов гостя, EPT-нарушения печатаются, отказ — fail-closed)
- [x] **Многолетник** — самособирающийся тулчейн: `./perennial.sh all` из свежего checkout сам собирает nightly + rust-src, проверяет qemu/xorriso, приносит Limine, растит луковицу, вяжет ISO и прогоняет и загрузку, и полную сессию Corolla по serial, сверяя каждый маркер (`smoke`/`shell`/`doctor`/`clean`); CI сам растёт через тот же скрипт
- [x] **Tunic** — слой политики, надетый на нектар — и на его горячий путь: пока оболочка снята, текут все метки; стоит надеть — по умолчанию всё отказано, и только явные гранты проходят: субъект, глагол (send/recv), метка. Каждый реальный вызов лейна Nectar проходит через одну дверь — эхо Corolla, реплики Bloom, сердцебиения Leaf (`checks` растёт сам); отказ виден и в счётчиках, и на лейне (`tunic:hot:deny`), грант открывает кран (`tunic:hot:sent`, `tunic:hot:recv`), а отозванный грант снова закрывает его ← *мы здесь*
- [ ] **Планировщик** — много цветений и листьев на одном таймере

## Сборка

Из свежего checkout одна команда выращивает весь сад — тулчейн, ядро, ISO и две проверенные загрузки:

```sh
./perennial.sh all
```

Отдельные шаги: `setup` (nightly + rust-src, проверка qemu/xorriso, Limine, пишет `perennial.lock`), `build`, `iso`, `smoke` (загрузка + маркеры ядра), `shell` (загрузка + полная сессия Corolla), `doctor` (прогноз погоды для инструментов), `clean`. Nightly и `rust-src` подтягиваются через `rust-toolchain.toml`; цель сборки — `x86_64-nerine.json`. Результат: `target/x86_64-nerine/debug/bulb` — ELF-образ ядра.

## Запуск

Ядро грузится загрузчиком [Limine](https://github.com/Limine-Bootloader/Limine) и печатает в COM1:

```sh
cargo build

mkdir -p isoroot/boot
cp target/x86_64-nerine/debug/bulb isoroot/boot/nerine.elf
cp ci/limine.conf isoroot/
cp limine/limine-binary/* isoroot/
xorriso -as mkisofs -o nerine.iso \
  -b limine-bios-cd.bin -no-emul-boot -boot-load-size 4 -boot-info-table \
  -eltorito-alt-boot -b limine-uefi-cd.bin -no-emul-boot \
  isoroot

qemu-system-x86_64 -M q35 -cpu max -m 512M -cdrom nerine.iso \
  -display none -serial stdio -no-reboot \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04
```

На машине с настоящим VT-x ядро поднимает VMX и запускает гостя по-настоящему; под TCG (без VMX) тот же сценарий проходит через shadow-бэкенд — оба пути оканчиваются строкой `guest:done` в COM1.

После загрузочного смоука ядро перестаёт умирать и начинает слушать: **Corolla**, интерактивный shell, отвечает в COM1:

```
corolla> help
help soil uptime nectar pollen bloom vm gh tunic sched exit
corolla> uptime
uptime:5.554s
corolla> gh on
greenhouse:hard
...
corolla> exit
corolla:bye
```

`soil` докладывает про APIC и таймер, `uptime` считает настоящие LAPIC-тики, `nectar`/`pollen`/`bloom`/`vm` показывают живые подсистемы, `gh on|off|vm` поднимает и опускает стеклянные стены оранжереи, `tunic on|off` надевает и снимает политику нектара, а `sched` показывает, как меристема делит тики между ростками. Чтобы скормить сессию скриптом:

```sh
{ sleep 8; printf 'uptime\ngh on\nexit\n'; } | qemu-system-x86_64 -M q35 -cpu max -m 512M \
  -cdrom nerine.iso -display none -serial stdio -no-reboot \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04
```
